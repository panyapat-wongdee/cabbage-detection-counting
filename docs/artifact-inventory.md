# Public artifact inventory

This inventory records how the current working-directory artifacts are treated before a public release.

| Location/pattern | Treatment | Reason |
|---|---|---|
| `original_dataset/`, `prepared/`, historical local exports | External/ignored | Dataset is externally hosted; generated layouts are reproducible and must not be redistributed here. |
| `runs/reproduced/*/checkpoints/`, `runs/reproduced/*/framework/`, `results/reproduced/**/records/`, `*.pt`, `*.pth`, `*.onnx`, `*.safetensors` | External/ignored | Checkpoints, native framework output, and raw prediction dumps do not belong in Git history; fine-tuned checkpoints are release assets with sidecars. |
| `runs/reproduced/` run metadata, `config.yaml`, `logs/`, `plots/`, `evaluation/` promotion documents | Tracked | The evidence a `reproduced_verified` claim rests on must stay checkable from Git history. |
| `results/reproduced/` metric reports, per-image rows, plots, `metadata.json`, `console.log`, comparison and complexity JSON | Tracked | Small, text-mostly evidence for numbers stated in the README; a published figure must be auditable without re-running inference. |
| `.ipynb_checkpoints/`, `__pycache__/` | Ignored | Local/generated caches. |
| `*.sarif` | Ignored | Tool-generated analysis reports are reproducible temporary artifacts. |
| `docs/environment/recovered-research-requirements.txt` | Public provenance snapshot | Only sanitized direct dependency evidence is retained; private historical source and outputs are excluded. |
| papers and publication exports | Exclude | Research context is represented by short protocol/citation documents; IEEE and dataset-paper PDFs remain excluded. |

The dataset described by the project is the Mendeley Data record with DOI
`10.17632/5cp2dyjczk.2`, associated with the article DOI
`10.1016/j.dib.2024.110699`. This repository does not claim ownership of its
images or annotations. Dataset content and model assets remain outside Git;
fine-tuned model assets require a separate release gate.

Training outputs live under `runs/reproduced/<run>/`, where `<run>` is the
model name or, for a controlled variant, `<model>-detector512`. Run folders group `checkpoints/`,
`logs/`, `plots/`, `evaluation/`, and (for Ultralytics) `framework/`. The
`evaluation/` folder holds the promotion evidence: the dataset, base-weight, and
evaluation documents, plus the staged prediction and metric files whose digests
the run metadata records. It records digests and official source URLs, never a
local cache path.

Evaluation outputs live under `results/reproduced/<run>/<split>/` as
`detection.json`, `counting.json`, `per_image.csv`, `metadata.json`,
`console.log`, `plots/`, and `records/`, with `summary.{md,json}` per model and
`model_comparison_<split>[_<variant>].{md,json}` and `model_complexity.json`
at the root. Everything except `records/`
is tracked, so every number quoted in the README can be checked against the
artifact that produced it; `records/` holds the large regenerable prediction and
target dumps and stays local, checksummed in each split's `metadata.json`.
Verified best checkpoints are distributed only as the per-run archives of the
`reproduced-checkpoints-v1.0.0` release, built from the promoted runs; there is
no separate local checkpoint view to maintain.

README figures live under `docs/figures/` and are regenerated by
`scripts/make_figures.py` from tracked comparison output and local evaluation
records. `counting_example.jpg` is the one adapted dataset image in the tree;
see [`licensing-and-attribution.md`](licensing-and-attribution.md).

SSDLite remains a `supplementary_unreported` experiment and YOLO12/YOLO26 are
`repository_extension` models; both must be labeled separately from the nine
architectures in the cited study.
